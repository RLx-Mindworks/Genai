Data Type Structure Summary:

User: Represents a system user.
  - Attributes:
    - id: Unique integer identifier for the user.
    - name: String representing the user's name.
    - email: String representing the user's email address.
    - role: Enumerated type representing the user's role (admin, editor, or viewer).

Project: Represents a project.
  - Attributes:
    - id: Unique integer identifier for the project.
    - title: String representing the project's title.
    - description: Text field providing a description of the project.
    - owner_id: Integer representing the ID of the user who owns the project (foreign key referencing User.id).

Task: Represents a task within a project.
  - Attributes:
    - id: Unique integer identifier for the task.
    - title: String representing the task's title.
    - status: Enumerated type representing the task's status (todo, in_progress, or done).
    - project_id: Integer representing the ID of the project to which the task belongs (foreign key referencing Project.id).

Relationships:
  - A User can own one or more Projects (one-to-many relationship).
  - A Project can have one or more Tasks (one-to-many relationship).

Potential System Requirements:
  - User management (creation, modification, deletion of users).
  - Role-based access control based on the User.role attribute.
  - Project management (creation, modification, deletion of projects).
  - Task management (creation, modification, deletion of tasks).
  - Ability to assign users as owners of projects.
  - Ability to associate tasks with projects.
  - Mechanisms to enforce referential integrity (e.g., preventing deletion of a User if they own Projects, or a Project if it has Tasks).
  - User interface components for managing users, projects, and tasks.
  - Database schema to represent the data structures and relationships.
